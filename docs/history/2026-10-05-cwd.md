# 2026-10-05 cwd の導入（0.3.0 / 0.3.1）

> git の履歴（`a88f5cf`, `99125f2`）から再構成。

## 困っていたこと

タスクは常に `/tmp` で動いていた。

- `/tmp` の外のファイルを触ると権限エラーになる。プロンプトに絶対パスを書いても解決しない。
- claude は起動したディレクトリから `CLAUDE.md`・`.claude/skills/`・`.mcp.json` を読む。`/tmp` で動く限りプロジェクトのスキルが使えず、プロンプトに回避策を書き込むしかなかった。

## 決めたこと

- `--cwd` を足し、生成スクリプトの `cd` をそのディレクトリにする（0.3.0）。
- プロンプトはプロジェクト側のスキルに置き、タスクは「スキルを実行して」の一行にする運用を README に書いた。プロンプトがバージョン管理され、手動実行と定期実行で同じ定義を使える。

## すぐ直したこと（0.3.1）

0.3.0 は cwd を plist の `WorkingDirectory` にも書いていた。launchd はこの chdir を自分で行い、TCC 保護下では拒否されるので、スクリプトが動く前にジョブが死んでいた。

- plist の `WorkingDirectory` は `/tmp` のままにし、cwd はスクリプトの `cd` だけで扱う。
- `test` で cwd が TCC 保護下にないかも確認するようにした。`/bin/bash` にフルディスクアクセスを与えても、claude のプロセスは別の TCC 主体なので EPERM のまま。
